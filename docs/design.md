# Hanahaku Feed 設計・実装計画

2026-10-08。対象は横浜の GREEN×EXPO 2027。

## 目的

公式の新着情報一覧を機械可読な JSON / RSS に変換し、個人の情報収集や許可された環境への組み込みに使える Python ライブラリ・CLI を作る。ソフトウェアは MIT ライセンス。公式情報の権利まで MIT に変更しない。

## 設計

- Python 3.11 以上、実行時の外部依存なし。認証情報不要。
- 取得先は `https://expo2027yokohama.or.jp/robots.txt` と `/news/index.html` の2つに固定。記事本文・PDF・画像は取得しない。
- HTML は実行せず解析し、タイトル・掲載日・カテゴリ・URLを抽出。形式変更や不正データでは失敗し、前回の正常な出力を保持。
- TLS 検証、リダイレクト拒否、タイムアウト、サイズ制限、robots.txt の確認、1時間キャッシュ、ETag / Last-Modified による条件付き取得。
- 正常取得後にスナップショットを比較し、新着・内容変更を検出。一覧落ちは削除と断定しない。初回は基準データの保存として扱う。
- 出力は JSON、RSS。利用元・取得日時・非公式ツールである旨を含める。HTML出力を持たず、RSS は XML エスケープする。
- 定期取得のサンプルは用意するが、ユーザー環境での常駐・定期実行はこの作業では開始しない。
- 公開用ファイルに取得したニュース、キャッシュ、個人情報、秘密情報を含めない。協会サイトの転載制限を README に明記。

## 選択した方式

ライブラリと CLI は、既存サイト・個人端末・CI のいずれでも使える。Webアプリはホスティングとアクセス管理が必要になり、今回は不要。全ページのクローラーは通信量と転載範囲が増えるため、最新一覧1ページに限定する。

## 実装・検証順序

1. パーサー：架空 HTML を使い、複数分類・相対URL・重複・異常日付・構造変更のテストを先に書き、失敗を確認して実装。
2. 取得処理：robots 拒否、ネットワーク障害、リダイレクト、304、キャッシュ、サイズ上限をテスト。失敗時は正常キャッシュを更新しない。
3. 出力・CLI：差分、JSON/RSS、初回基準、障害時の既存出力保持、同時実行抑制をテスト。
4. 文書・配布：README、MIT、SECURITY、CONTRIBUTING、CI、定期実行例。第三者利用や既存のセキュリティ実績を主張しない。
5. 実サイト取得・再実行・クリーンな仮想環境へのインストールを確認し、配布物に私的データが入っていないことを確認。
